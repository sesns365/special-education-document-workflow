# 特教公文工作流

## 核心規則

先讀取專案根目錄的「特教公文工作流使用說明書.md」，並以該檔案及當次使用者指示為權威。將本技能視為本專案的固定操作流程，不要把規則套用到其他專案。

將專案根目錄確認為同時包含下列資料夾的位置：

- 00原始公文備份
- 01待辦公文
- 02已完成待歸檔
- 03歸檔公文
- 90_每日處理紀錄
- 99_系統紀錄

保留原始公文及個資安全。不要自動簽核、正式送件、刪除原始檔、決定學生服務，或在沒有明確指令時搬移案件。

## 文件閱讀能力

依來源格式選擇已啟用的閱讀能力：

- 文字型 PDF：使用 PDF 文字／結構化 PDF 讀取能力；需要轉成可搜尋文字時可使用 MarkItDown。
- 掃描 PDF 或掃描影像：使用 PDF OCR；OCR 不足時標示需人工核對，不要自行補猜。
- DOCX、XLSX、PPTX：使用 Microsoft Office 文件讀取能力；需要純文字整理時可使用 MarkItDown。
- ZIP：先檢查壓縮檔清單，再安全解壓到案件工作副本，並對其中的 PDF、Office 或掃描檔逐一使用對應能力；保留原始 ZIP。
- 若對應能力未啟用或讀取失敗，明確回報缺少的格式能力，停止該檔案分析，不要以檔名或不完整預覽假裝完成。

本 Repository 不複製或安裝通用閱讀技能；共享者需在自己的 Codex 環境啟用可用的 PDF、OCR、Office 或 MarkItDown 能力。

## 機密文件隔離

「00原始公文備份」是 AI 的待讀取入口，不是機密隔離區。輸入「開工」前，只將已獲使用者授權 AI 讀取的來源放入該資料夾。

不希望 AI 讀取的機密、密件、學生個案資料或未經核准的公文，應放在專案根目錄及目前 Codex 工作區之外的私有資料夾，或不要提供給此工作區。只放在其他未掃描子資料夾，不能視為完整安全邊界；若使用者明確要求，AI 仍可能讀取可存取的檔案。

若 00原始公文備份 中出現檔名已標示「機密」、「密件」、「不可讀取」或其他禁止分析字樣，先停止，不開啟檔案內容，請使用者自行移出並另行處理。

## 指令分流

### 專案初始化

執行以下工作：

1. 檢查說明書、六個主要資料夾、待辦分類資料夾及目前案件數量。
2. 檢查 01待辦公文、02已完成待歸檔、03歸檔公文及 90_每日處理紀錄的目前狀態。
3. 回報待辦、已完成待歸檔、已歸檔及缺少分析資料的案件。
4. 不搬移、不改名、不刪除任何案件。

### 開工

只處理放在 00原始公文備份 中、且已獲使用者授權 AI 讀取的 PDF、ZIP、DOC、DOCX、XLS、XLSX、PPT、PPTX 及掃描影像（JPG、JPEG、PNG、TIF、TIFF），並保留原始檔案及原始檔名。

先依「文件閱讀能力」選擇格式路由，再對每份新來源：

1. 使用檔案雜湊避免重複處理。
2. 安全解壓 ZIP，將主文與附件平鋪放入同一案件資料夾，不建立附件子資料夾。
3. 讀取主文及必要附件，記錄收文日期、公文名稱、期限、研習日期、原文依據及下一步。
4. 依主要辦理行動分類並放入 01待辦公文 的子資料夾：
   - 00轉知公文：只需轉知或存查；單純轉知研習資訊歸此類。
   - 01業務處理：需要回覆、校內彙整、填報、送件、核示、經費處理，或需要報名、派員、核准、繳費、回報的研習。
   - 02申請服務：申請特教相關專業人力、專業服務、學生服務、服務需求或其他資源。
   - 99待分類：資料不足或主要辦理方向無法確認。
5. 建立案件內的文字檔、metadata.json 及擬辦建議.md。至少記錄收文日期、主旨、處理類型、分類理由、期限、研習日期、優先層級、狀態、下一步、等待對象及來源雜湊。
6. 依期限或實際研習日為案件資料夾加上提醒尾註。沒有確定日期時不要猜測。
7. 重新掃描所有尚未完成的 01待辦公文，建立或更新 90_每日處理紀錄內的民國日期_待辦公文總表.md。

每日總表至少列出案件名稱、處理類型、收文日期、期限或研習日期、狀態、下一步及來源案件資料夾。依下列順序排列：

1. 逾期或今天到期。
2. 三日內到期。
3. 七日內到期。
4. 八日以後到期。
5. 沒有明確期限。

同一期限群組內，依申請服務／填報送件、等待他人回覆、等待主管核示、一般業務處理、純轉知／研習／存查排序。研習案件使用實際研習日期作為期限參考，不要只依檔名猜日期。

### 收工

只檢查 01待辦公文 中尚未完成的案件：

- 更新狀態、下一步、期限及逾期／三日內／七日內提醒。
- 更新當日待辦公文總表。
- 產生或更新 90_每日處理紀錄內的民國日期_公文處理紀錄.md。
- 提醒已標示完成但仍留在 01待辦公文 的案件。
- 不自動搬移、不刪除案件。

案件只有在承辦人確認完成後，才將整個案件資料夾人工移到 02已完成待歸檔；必須連同附件、文字檔、metadata.json 及擬辦建議.md 一起移動。

### 歸檔

只有使用者明確輸入「歸檔」時，才執行搬移。

只處理 02已完成待歸檔 中的完成案件，不處理 00原始公文備份、01待辦公文或已在 03歸檔公文 的內容。

逐案執行：

1. 從 metadata.json、擬辦建議.md、主文或附件確認原始收文日期；無法確認精確日期時留在 02並記錄原因，不得猜測。
2. 依收文日期建立或使用 03歸檔公文 的民國年月資料夾，例如民國 115 年 8 月存放於 11508。月份依收文日期，不依完成日期、期限或研習日期。
3. 將歸檔名稱整理為「收文日期_公文名稱(日期止／研習日期)」。
4. 單一檔案保留副檔名並改成上述名稱；多檔案案件整個搬移，並將案件資料夾改成上述名稱。保留附件、文字檔、metadata.json 及擬辦建議.md；附件檔名不任意改寫。
5. 移除系統流水號、下載識別碼、「公文原檔」及與主旨無關的冗長前綴。沒有確定期限或研習日期時省略尾註；多個期限沿用「(0904止、0930止)」，研習優先使用「(0820研習)」。
6. 不覆蓋同名檔案或資料夾。相同來源雜湊視為已歸檔並略過；不同內容的同名案件留在 02並列為命名衝突，等待人工處理。
7. 完成後建立或更新 90_每日處理紀錄內的民國日期_公文歸檔紀錄.md，列出已移動、已略過、日期不足及命名衝突。
8. 確認歸檔目標存在、來源已移除且檔案雜湊未變化。不要刪除 00原始公文備份 的原始 PDF 或 ZIP。

## 個資與回報

待辦總表及一般索引使用案件代碼，不直接寫學生姓名、診斷、障礙類別、身分證字號、地址、電話或家庭資料。完整個案資料只在必要的案件資料夾內處理。

回報時清楚列出：

- 開工：新增案件、分類結果、期限、分類不確定項目及總表位置。
- 收工：逾期、近期到期、等待回覆、已完成但未移動及紀錄位置。
- 歸檔：成功移動、月份目標、標準化名稱、略過案件、日期不足及命名衝突。

使用繁體中文回覆，直接說明結果。若使用者只是詢問規則或修改說明書，不要擅自執行開工、收工或歸檔。
